# Contributing

Thanks for helping improve Brynn Interactive.

1. Open an issue before large changes so the scope can be discussed.
2. Keep pull requests focused and explain the user-visible behavior.
3. Do not include tokens, credentials, chat logs, personal data or local
   application state in commits, screenshots or test fixtures.
4. Add or update tests for behavior changes where practical.
5. Run the relevant test suite and Python compilation checks before opening
   a pull request.
6. Do not change webhook routes, OAuth scopes or security controls without
   documenting the impact.
7. Do not submit third-party assets unless their redistribution rights are
   clear and documented.
